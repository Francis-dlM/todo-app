## 2. 产品目标

### 2.1 核心问题

现代用户面临信息碎片化、任务分散在多个工具中的困境，导致：

- 任务遗漏、优先级混乱；
- 缺乏统一的"今日事项"视图，难以聚焦当天工作；
- 多设备间任务状态无法同步，降低执行效率。

### 2.2 三大产品目标

1. **聚焦当日，减少遗漏**：提供"我的一天"视图，让用户每天明确知道要做什么，形成任务闭环习惯。
2. **灵活组织，适应不同场景**：支持清单（List）、标签、截止日期等多维度组织任务，满足个人与轻量团队的需求。
3. **简洁高效，降低使用门槛**：极简交互设计，核心操作（添加/完成/删除任务）不超过 2 步，让用户专注于执行而非管理工具本身。

## 3. 用户角色与场景

### 3.1 主要用户画像

| 角色 | 描述 | 核心诉求 |
|------|------|------|
| **职场个人用户** | 25-45 岁白领，每天需处理工作与生活双线任务 | 快速记录、今日聚焦、不遗漏 |
| **学生用户** | 18-25 岁在校生，管理课程作业、考试计划 | 截止日期提醒、分类清晰 |
| **自由职业者/轻创业者** | 独立工作者，需管理多个项目任务流 | 多清单管理、子任务拆解 |

### 3.2 典型使用场景

**场景 A：早晨规划（职场用户）**
> 小王每天早上打开 App，查看"我的一天"视图，将今天需要完成的任务手动加入当日列表，并为重要任务设置提醒时间，开启高效一天。

**场景 B：课程作业管理（学生用户）**
> 小李为每门课程建立独立清单，在清单中添加各次作业任务并设置截止日期。接近 deadline 时收到提醒，不再遗漏提交。

**场景 C：项目任务拆解（自由职业者）**
> 设计师小张接到一个品牌设计项目，在 App 中创建"品牌项目 A"清单，将项目拆解为多个子任务（调研、草图、定稿等），逐步标记完成，清晰追踪进度。

**场景 D：跨设备使用**
> 小王在电脑端添加了一个下午的会议任务，下午出门前用手机查看，任务已同步显示，并在会议前 15 分钟收到推送提醒。

## 6. 核心功能详述（P0 功能）

### 6.1 任务快速创建（P0-01）

**交互逻辑**：
- 每个视图（我的一天、清单详情）底部或顶部有固定输入框，placeholder 为"添加任务，按回车保存"。
- 用户输入标题后按 `Enter` 完成创建；按 `Escape` 取消输入。
- 创建成功后，输入框清空，新任务出现在列表顶部（或底部，可配置）。
- 支持点击输入框右侧"更多"按钮，直接打开任务详情页进行完整填写。

**边界条件**：
- 标题为空时按回车：不创建任务，轻微抖动提示。
- 标题最大长度：500 字符，超出截断并提示。
- 连续快速创建（不等待动画）：需队列化处理，保证不丢失。

---

### 6.2 任务完成/撤销完成（P0-02）

**交互逻辑**：
- 任务左侧圆形复选框，点击后：
  - 复选框变为选中态（填充色 + 对勾）；
  - 任务标题出现删除线，行背景轻微变灰；
  - 300ms 后任务移至列表底部"已完成"折叠区。
- 点击"已完成（N）"可展开/折叠已完成任务。
- 在已完成区域再次点击复选框：任务恢复为未完成状态，移回主列表顶部。

**边界条件**：
- 当日清单中完成的任务：次日清除出"我的一天"，但在原始清单中保留。
- 批量完成：暂不支持（P1 迭代考虑）。

---

### 6.3 多清单管理（P0-04）

**交互逻辑**：
- 左侧边栏展示固定视图（我的一天、重要、计划内、任务——默认收件箱）+ 用户自定义清单列表。
- 点击"新建清单"：弹出内联输入框，输入名称回车确认，自动生成随机颜色图标。
- 清单右键菜单：重命名、更改颜色/图标、删除清单。
- 删除清单：弹出确认对话框，提示"清单及其中所有任务将被永久删除"；清单内任务数 > 0 时需二次确认。

**边界条件**：
- 清单名称最大长度：100 字符。
- 清单数量上限（本地版）：50 个，超出提示。
- 不可删除系统内置视图（我的一天、重要、计划内、任务）。

---

### 6.4 "我的一天"视图（P0-06）

**交互逻辑**：
- 每天打开 App 时，若当日"我的一天"为空，显示欢迎提示和"智能推荐"按钮（推荐今日截止或逾期任务）。
- 用户可手动将任意清单中的任务"加入我的一天"（任务详情页 / 右键菜单）。
- 视图顶部展示当天日期和天气（天气为 P2 功能，MVP 阶段仅展示日期）。
- 次日 00:00，已加入"我的一天"但未完成的任务自动移出，回归原始清单（不删除）；完成的任务随已完成区域处理。

**边界条件**：
- 跨天使用（App 长时间后台）：首次交互时检测日期变更，触发自动清空逻辑。
- 同一任务不能被重复添加到"我的一天"。

---

### 6.5 任务详情页（P0-07）

**包含字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| 任务标题 | 文本输入 | 可内联编辑 |
| 加入我的一天 | 开关 | 切换是否在当日视图显示 |
| 重要标记（★） | 开关 | 切换标星状态 |
| 截止日期 | 日期选择器 | 含"清除"选项 |
| 提醒时间 | 日期+时间选择器 | 需截止日期或独立设置 |
| 重复 | 下拉选择 | 无 / 每天 / 工作日 / 每周 / 每月 / 每年 / 自定义 |
| 所属清单 | 下拉选择 | 可移动任务到其他清单 |
| 子任务 | 列表 + 输入 | 可添加、完成、删除子任务 |
| 备注 | 多行文本 | 纯文本，支持换行 |
| 创建时间 | 只读 | 显示在底部 |

**交互逻辑**：
- 详情页以右侧抽屉（Drawer）形式呈现，不遮挡任务列表。
- 所有字段实时自动保存（无需点击保存按钮）。
- 底部"删除任务"按钮，需确认。

## 7. UI/UX 设计建议

### 7.1 整体风格

- **设计语言**：参考 Microsoft To Do 的简洁现代风，采用 Material Design 3 规范。
- **主色调**：蓝色系（#0078D4，微软蓝）或可由用户为每个清单自定义主题色。
- **字体**：无衬线字体，正文 14px，标题 16px，充足行距（1.6）保证可读性。
- **圆角**：统一使用 8px 圆角卡片，营造柔和感。
- **动效**：任务完成时的勾选动画（300ms）、列表项滑入滑出（200ms），保持克制。

## 8. 技术约束与假设

### 8.1 平台

- **MVP 阶段**：Web 端优先（桌面浏览器），响应式兼容移动端浏览器。
- **后续**：可通过 PWA 打包为可安装应用；更远期考虑 React Native 移动原生端。

### 8.2 技术栈建议

| 层级 | 技术选型 | 理由 |
|------|----------|------|
| 前端框架 | React 18 + Vite | 生态成熟，构建速度快 |
| UI 组件库 | MUI v5 + Tailwind CSS | MUI 提供完整组件，Tailwind 补充自定义样式 |
| 状态管理 | Zustand | 轻量，适合中型应用，无样板代码 |
| 本地存储 | IndexedDB（via Dexie.js） | 比 LocalStorage 容量大，支持结构化查询 |
| 日期处理 | dayjs | 轻量，API 友好 |
| 拖拽排序 | @dnd-kit/sortable | 支持无障碍访问，性能好 |
| 通知 | Web Notifications API | 浏览器原生推送，无需后端 |

### 8.3 数据存储方案

**MVP 阶段（本地存储）**：
- 所有数据存储在 IndexedDB，包含 `tasks` 和 `lists` 两张表。
- 数据模型：

```typescript
// 清单
interface TaskList {
  id: string;          // UUID
  name: string;
  color: string;       // 主题色
  icon: string;        // emoji 或图标名
  order: number;       // 排序权重
  createdAt: Date;
}

// 任务
interface Task {
  id: string;          // UUID
  title: string;
  note?: string;       // 备注
  listId: string;      // 所属清单 ID
  isCompleted: boolean;
  isImportant: boolean;
  isMyDay: boolean;    // 是否在我的一天
  myDayDate?: string;  // 加入我的一天的日期（YYYY-MM-DD）
  dueDate?: Date;      // 截止日期
  reminder?: Date;     // 提醒时间
  repeat?: RepeatRule; // 重复规则
  subtasks: Subtask[]; // 子任务列表
  order: number;       // 清单内排序
  createdAt: Date;
  completedAt?: Date;
}
```

**P2 阶段（云端同步）**：
- 引入后端 API（Node.js + PostgreSQL 或 Supabase BaaS）。
- 使用 JWT 认证，支持 Google/GitHub OAuth 登录。
- 实时同步方案：WebSocket 或轮询（5s）。
